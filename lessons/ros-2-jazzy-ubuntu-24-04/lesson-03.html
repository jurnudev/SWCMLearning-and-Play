Lesson 03

Workspace & Remote Control

"เข้าใจโครงสร้างพื้นที่ทำงาน และการเขียนโค้ดแบบ Live บนหุ่นยนต์"

1. เข้าใจหลักการ "พื้นที่ทำงานแยกส่วน"

⚠️ ข้อควรระวังที่มือใหม่มักสับสน!
ในโลกของ ROS 2 พื้นที่ทำงาน หรือ Workspace ที่เราสร้างขึ้นบนเครื่องคอมพิวเตอร์ (Client) จะไม่ส่งข้อมูลไปที่หุ่นยนต์ (Raspberry Pi) โดยอัตโนมัติ

💻 ฝั่ง Client (Laptop)

โค้ดที่เขียนที่นี่ จะถูกเก็บไว้ใน Hard Drive ของคอมพิวเตอร์ ใช้สำหรับทดสอบจำลอง (Simulation) เท่านั้น

🍓 ฝั่ง Host (Raspberry Pi)

โค้ดที่ต้องการให้หุ่นยนต์วิ่งจริง ต้องถูกเก็บไว้ใน SD Card ของ Raspberry Pi เท่านั้น

2. เทคนิคการเขียนโค้ดแบบ Live (VS Code Remote-SSH)

เรามีทางเลือก 2 ทางในการพัฒนาโปรเจกต์ครับ:

ทางเลือกที่ 1: เขียนบน PC แล้วค่อย Upload (สำหรับผู้เริ่มต้น)

ถ้า Raspberry Pi ยังไม่พร้อม หรือยังไม่ได้ลงระบบ ให้เขียนและทดสอบบนคอมพิวเตอร์ไปก่อน จากนั้นค่อยใช้คำสั่ง scp หรือแฟลชไดร์ฟก๊อปปี้ไปวางที่หุ่นยนต์ภายหลัง

ทางเลือกที่ 2: Remote-SSH (วิธีแนะนำแบบมืออาชีพ)

ใช้โปรแกรม Visual Studio Code ติดตั้งส่วนขยาย "Remote - SSH" เพื่อเชื่อมต่อจากคอมพิวเตอร์เข้าไปยัง Raspberry Pi โดยตรง

  • ✅ เขียนโค้ดบนจอคอมพิวเตอร์ที่ลื่นไหล แต่ไฟล์เซฟลงบนตัวหุ่นยนต์ทันที
  • ✅ ไม่ต้องต่อจอมอนิเตอร์ คีย์บอร์ด แยกให้ Raspberry Pi
  • ✅ แก้โค้ดแล้ว Build บนหุ่นยนต์ได้แบบ Real-time

3. โครงสร้าง Colcon Workspace

พื้นที่ทำงานของ ROS 2 จะใช้ระบบที่เรียกว่า colcon โดยเราต้องสร้างโฟลเดอร์หลักขึ้นมาดังนี้:

# สร้างโฟลเดอร์สำหรับทำงาน (แนะนำชื่อ ros2_ws) mkdir -p ~/ros2_ws/src cd ~/ros2_ws colcon build # สั่งสร้างโครงสร้างครั้งแรก

📁 /src

"แหล่งรวมโค้ดต้นฉบับ"

📍 จุดเดียวที่คุณต้องแก้ไข
โค้ด Python/C++ ของเราจะอยู่ที่นี่ทั้งหมด

📁 /build & /install

"ไฟล์ระบบที่เกิดจากการคอมไพล์"

ห้ามแก้ไขไฟล์ในโฟลเดอร์เหล่านี้ด้วยตัวเอง เพราะระบบจะสร้างขึ้นใหม่ทุกครั้งที่สั่ง build

🚀 ข้อควรจำ: กฎเหล็กของ Workspace

1 ต้อง colcon build ที่ Root เท่านั้น
ห้ามสั่ง build ภายในโฟลเดอร์ src หรือโฟลเดอร์ย่อยเด็ดขาด

cd ~/ros2_ws # เข้ามาที่โฟลเดอร์นอกสุดก่อนเสมอ colcon build

2 ต้อง Source ไฟล์หลัง Build ทุกครั้ง
เพื่อให้ระบบ ROS รู้ว่ามีโค้ดใหม่หรือ Package ใหม่เกิดขึ้น

source install/setup.bash

💡 เคล็ดลับ: ถ้าเปิด Terminal หน้าต่างใหม่ อย่าลืมสั่ง source ก่อนใช้งานเสมอ!

4. คำสั่ง Terminal ที่ใช้บ่อย

คำสั่ง หน้าที่
colcon build คอมไพล์โค้ด (สั่งงานที่ Root ของ Workspace เท่านั้น)
source install/setup.bash อัปเดตระบบให้รู้จักโค้ดล่าสุด (สั่งหลัง build เสร็จ)
ros2 pkg create --build-type ... สร้าง Package ใหม่ (ต้องทำภายในโฟลเดอร์ src)
ros2 run [package] [node] สั่งให้หุ่นยนต์เริ่มทำงาน

🏁 สรุปใจความสำคัญ

"จำไว้ว่า โค้ดอยู่ที่ไหน งานทำงานอยู่ที่นั่น"
หากต้องการให้หุ่นยนต์ฉลาดขึ้น เราต้องส่งโค้ดไปรันที่สมองของมันโดยตรง การฝึกใช้ Remote-SSH จะช่วยให้อาจารย์และนักเรียนทำงานได้สะดวกขึ้นหลายเท่าตัวครับ
